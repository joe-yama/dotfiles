# ローカル LLM 日次調査 2026-11-16

対象機: MacBook Pro M4 Max 40C GPU / 128GB / macOS 26.x。構成は llama-swap → mlx-serve (Qwen3.8-Flash-Next の 2 パック)。
調査はクラウドサンドボックスで行い、本機では何も実測していない。数値は出典付きの他者実測か公式値。当機向けの値には「推定」「未実測」と付けた。
調査範囲は 2026-11-12〜11-16 (前回 `docs/llmdaily20261112.md` 以降)。リポジトリには 11-12 のレポート追加以降コミットが無い。11-12 の推奨 (llama-swap 更新、本命 iQ A/B) は未実施と判断した。

## (a) TL;DR

- **モデル: 据え置き**
- **mlx-serve: 導入済み 26.11.2 / 最新リリース 26.11.2 → 据え置き。** main に次の変更が積まれている (未リリース、v26.11.2 以降 97 コミット、11-15 時点)。
  - 前回報告した #1147 (preflight の新しい判定式、qwen4_exp の層ごとロード) と #1163 (prefill 保留中のキャンセルで SIGSEGV)。
  - 今回の新規分: 新しいビルドで初めてモデルをロードしたときの Metal カーネル warm-up (アイドル時に実行。`--warmup-full` を付けると ready の前に済ませる)。メモリ拒否のエラーに `reason: "memory_refused"` が付く。
  - prefill 中に他のリクエストが止まる問題と、プロセスを跨ぐスワップの解放待ちには変更が無い。
- **llama-swap: 導入済み v270 / 最新 v273 → 更新推奨 (低優先)。** 理由: v272 の #1319 で、1MiB を超えるボディのリクエストで上流のエラーが 200 に化ける不具合が直った。v273 の `fit` selector は当機の 2 エントリ排他構成では使わない。

補足: 本命の候補として新しく現れたのは 2 つ。どちらも「乗り換え推奨」には至らない。
- **Swift 1.5** (UkisAI による Flash-Next の fine-tune で、思考トークンを 56% 削減): 非 gated の mlx-serve パックが 11-14 に出た。M4 Max 128GB での実測が添えられている → (e)-3 で任意の評価枠として提示する。
- **Edge0-145B** (Flash-Next の expert 層を作り直したもの。TB2.1 86.5 は自己申告): 専用エンジンが必要で、mlx-serve では動かない。

### 3. (任意・新規) Swift 1.5 を本命の評価枠として A/B する

Flash-Next の fine-tune で、思考トークンを削った版。当機は thinking を既定 on で運用しているので、待ち時間の短縮が見込める。
ただし命令追従が落ちる兆候があり、ライセンス表記にも食い違いがある。このため「乗り換え推奨」にはせず、評価枠の候補にとどめる。

- **(a) リポジトリと形式**
  - `pgmharikrishnan/Swift1.5-Qwen3.8-Flash-Next-MLX-Serve-mixed-4-8bit` (rev 629259c、107.3GB、112 ファイル、非 gated、`library_name: mlx-serve`)。
  - qwen4_exp で、mlx-serve 公式の `tests/convert_qwen38_flash_next.py` で変換されている。配分は `ddalcu/…-mixed-4-8bit` と同じ: routed experts / embed 4bit g64、attention / GDN / shared expert / lm_head 8bit g64、n-gram 表 4bit g32 (`ngram_table.bin` 32GiB、mmap)。MTP と vision を同梱。
  - **imatrix ではない** (旧 ARC4NUM と同じ min-max 量子化。旧 ARC4NUM の同配分パックは BF16 比 KL 0.18 で、iQ 版の 0.11 より劣る)。
  - mlx-serve で動くことはパック作者が確認済み (26.11.1、M4 Max 128GB)。26.11.1 の「他者の Flash-Next パックが読める」修正以降は対応範囲内。
  - ⚠️ **ライセンス**: base の `ukisai/Swift1.5-Qwen3.8-Flash-Next` は gated で、`swift-open-license-1.0` を名乗っている。一方、このパックは Qwen Community License 1.0 と書いている。私用であっても、取得前に base の利用条件を確認すること。
- **(b) 常駐**
  - 作者実測で weights 75.3GB (70.1GiB)、102K 窓での active は 80〜82GB。
  - 当機の無検閲 iQ パック (≈71GB、preflight の必要空き ≈77GB) と同程度と推定する。11-08 の A/B で無検閲 iQ パックのスワップは 4 回とも拒否されていないので、`settle` の下で通る見込み。
  - ディスクに 107GB の空きが要る。
- **(c) 期待 tok/s と品質**
  - パック作者の実測 (M4 Max 128GB、26.11.1、Flash-Next の mixed-4-8bit と同じバイナリで比較。**順序は入れ替えておらず Swift が後**、窓 102,400):
    - decode (MTP 込み): short 57.8 vs Flash-Next 74.0 (−22%)。64K 文脈では 44.2 vs 27.1 (+63%)。
    - prefill: 64K で 748 vs 414。
    - 18 ケースの品質スイート: 81.2 vs 84.4。instructions が 62.5 vs 100、structured が 62.5 vs 37.5、tools は 100 で同じ。
  - 長文側の差が大きすぎる。キャッシュ状態の違い (作者も caveat として明記) を疑うべきで、**当機の値は未実測**。
  - UkisAI の公表値 (BF16、xhigh、5 seed):
    - GPQA-D 89.8 → 89.6 (平均思考トークン 17.7k → 7.8k)
    - LCB v6 88.4 → 90.4 (17.8k → 9.8k)
    - IFBench 73.2 → 70.1
    - TB2.1 は出力トークンが +12% で、スコアは同等 (条件は公式値と異なる)
  - コーディング / エージェント指標 (SWE-bench 系) は公表されていない。
  - **期待される効果**: thinking を on にしたときの応答の壁時計時間が、おおむね半分になる見込み (推定)。**懸念**: 命令追従 (IFBench −3.1、作者スイートの instructions −37.5) と、Hermes の構造化 tool_calls への影響。
