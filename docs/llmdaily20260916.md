# ローカル LLM 日次調査 2026-09-16

対象: MacBook Pro M4 Max 40C GPU / 128GB / macOS 26.x、llama-swap → mlx-serve (Qwen3.8-Flash-Next 2 パック)。
調査はクラウドサンドボックスで実施。本機での実測は一切行っていない。数値は出典付きの他者実測または公式値で、当機に当てはめた推定は「推定」「未実測」と明記する。

## (a) TL;DR

- **モデル: 据え置き** — 過去 1 週間で公開されたオープンウェイトのうち、wired 90GB 以内に収まって Flash-Next (SWE-bench Pro 62.5 / DeepSWE 1.1 58.7) を上回るものは無い。DeepSeek-V4.1-Flash (09-10) は Terminal-Bench 2.1 90.6 で Claude Opus 5.0 (89.1) を上回るが 552B 級で当機に載らない。
- **mlx-serve: 導入済み 26.9.1 / 最新リリース 26.9.3 (2026-09-16 公開) → 26.9.3 へ更新推奨。** 26.9.2 (09-09) で「長文 prefill 中の Metal OOM でサーバが即死する」問題 (#353) が「そのリクエストだけ失敗」に変わり、prefix cache 予算の不具合 (#364) も修正。26.9.3 で MoE decode と Flash-Next prefill が高速化、JSON schema 出力で thinking が切れなくなり、長い system prompt を共有する agent セッションの毎ターン再 prefill (#390) が直った。公開当日で第三者の運用報告は無いため、旧版ディレクトリを残したまま切り替え、`docs/bench/` の short / 24k を再走して確認すること。
- **llama-swap: 導入済み v252 / 最新 v255 (2026-09-06) → 更新推奨 (低優先)。** v254/v255 で `setParams` に「未指定時のみ設定」の `?` サフィックスが入り、`enable_thinking?: true` と書けばクライアント側の `enable_thinking: false` を潰さずに既定 on を維持できる (現行の弱点「thinking 既定を切り替えるサーバフラグが無い」への実用的な対処)。

## (e) 推奨アクション

### 1. mlx-serve 26.9.3 へ更新 (推奨)

`run_onchange_after_install-mlx-serve.sh` の差分。sha256 は本日サンドボックスで GitHub Release の tarball (72,072,610 bytes) を直接取得して計算した値。Formula (`Formula/mlx-serve.rb`) は 09-16 07:00 UTC 時点でまだ 26.9.2 (`f2dd5f80…`) を指しており、26.9.3 の値は未掲載。

```diff
-MLX_SERVE_VERSION="26.9.1"
-MLX_SERVE_SHA256="b9bb5178ac2dcfbfa232ffa1e6ce77e87a6408a540cbdaabb66d101d667590b0"
+MLX_SERVE_VERSION="26.9.3"
+MLX_SERVE_SHA256="05863d67dc823798ac072ef72824360cbbd868734d2f79516bba153349eef794"
```

段階更新したい場合の 26.9.2: `f2dd5f80d4e50e4ebd57b28e70ce79ed95a657337360784975b610cec50400af` (Formula 記載値と一致、サンドボックスでの再計算でも一致)。

手順: `chezmoi apply ~/.local/opt/…` (script 再実行) → `launchctl kickstart -k gui/$UID/local.llama-swap` → `~/.local/opt/mlx-serve/current/mlx-serve-macos-arm64/mlx-serve --version` → Hermes cron (09:00〜09:30 JST) を避けて `docs/bench/run_ab.sh` の short / 24k を本命・無検閲で各 3 run。確認点: (1) decode が 70 / 56 tok/s を下回らない、(2) `footprint` の wired ピークが 8192 刻み prefill で +3GB 程度に収まる、(3) tools 4 問で構造化 `tool_calls` が返る (26.9.2 でツール引数の扱いが変わっている)、(4) `enable_thinking: true` 注入で thinking が出る。config.yaml のフラグ (`--ctx-size 262144 --timeout 0 --prefix-cache-mem 12GB --prefix-cache-entries 64`) は 26.9.3 の `docs/cli.md` に全て残っており変更不要。旧版は `~/.local/opt/mlx-serve/mlx-serve-26.9.1` に残るので、戻すときは version / sha256 を元に戻して apply。

更新後の追加 A/B (任意、未実測): `--mtp` を両パックで再測。26.9.2 以降は効かない文脈長で自動 off になるため、本命パックでの負が消えている可能性がある。

### 2. llama-swap v255 へ更新 + `?` 構文 (低優先)

`brew upgrade llama-swap` (Brewfile は tap 参照のみで版固定なし) → kickstart。更新後、本命エントリのみ「未指定時だけ thinking on」にする案:

```yaml
  qwen38-flash-next:
    filters:
      setParams:
        enable_thinking?: true   # v254+ の set-if-undefined。opencode / dsh が明示した false を尊重する
```

無検閲エントリ (Hermes 既定) は Hermes が thinking 常時 on を前提にしているので `enable_thinking: true` (強制) のまま据え置く。`?` の挙動は `docs/config.example.yaml` (369〜376 行) の記述に基づく。適用前に `llama-swap -validate` で構文確認。
