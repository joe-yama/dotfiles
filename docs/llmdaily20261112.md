# ローカル LLM 日次調査 2026-11-12

対象機: MacBook Pro M4 Max 40C GPU / 128GB / macOS 26.x。構成は llama-swap → mlx-serve (Qwen3.8-Flash-Next の 2 パック)。
調査はクラウドサンドボックスで行い、本機では何も実測していない。数値は出典付きの他者実測か公式値で、当機向けの値には「推定」「未実測」と付けた。
調査範囲は 2026-11-08〜11-12 (前回 `docs/llmdaily20261108.md` 以降)。新モデルは 11-05 公開分から見た。

## (a) TL;DR

- **モデル: 据え置き**
- **mlx-serve: 導入済み 26.11.2 / 最新リリース 26.11.2 → 据え置き。** main には当機に効く変更が積まれている (未リリース)。
  - **ロード前 preflight の空き判定の見直し (#1147、11-11)**: 「総メモリ − (wired + compressor) − OS 予約」で判定する。11-03〜04 に起きた Lightroom / Docker 常駐時の起動拒否は、この変更で解消する見込み。
  - **qwen4_exp の trunk を 1 層ずつ評価してロードする (#1147)**: 高負荷時に GPU タイムアウトで落ちていたのを防ぐ。
  - **prefill 待ち中に切断されたリクエストでの SIGSEGV 修正 (#1163)**。

  プロセスを跨ぐスワップ直後の空き判定は、新しい式でも旧プロセスの wired が残っている間は拒否になる。`settle` は引き続き必要。
- **llama-swap: 導入済み v270 / 最新 v272 → 更新推奨 (低優先)。** 理由: v272 の #1319 で、1MiB を超えるリクエストボディ (`Expect: 100-continue`) のときに上流の 400/500 がクライアントへ 200 として届く不具合が直った。

補足: 本命パックの imatrix 版 `ddalcu/…-MLX-Serve-iQ-MLX-4.7bpw` を、10-26 のレポートで任意の候補として挙げていた。今回、根拠が 2 つ増えた → (e)-2 で A/B を推奨 (任意)。
1. nace-ai が第三者として BF16 比 KL を測った。iQ 4.7bpw は 0.066 で、素の 4bit 系 (0.14〜0.25) の半分以下。
2. 同じビット配分の無検閲 iQ パックについて、当機の 11-08 の A/B で速度低下が無いことを確認済み。

- それ以外は UI と内部パッケージ化。config の互換性を壊す変更は v271 / v272 の changelog に無い。

### 2. (任意) 本命パックを ddalcu iQ-MLX-4.7bpw で A/B する

10-26 のレポート (e)-3 の再提起。今回、新しい根拠が加わった。

- **(a) リポジトリと形式**: `ddalcu/Qwen3.8-Flash-Next-MLX-Serve-iQ-MLX-4.7bpw` (rev a0e89db、107.33GB、113 ファイル、非 gated、`library_name: mlx-serve`)。
  - mlx-serve 作者の公式パックで、qwen4_exp。
  - **現行の無検閲パックと同じビット配分とファイル構成** (無検閲側はこれを abliterated 重みで作り直したもの)。
  - 現行の本命パック `ddalcu/…-MLX-Serve-4bit` は HF から消えていて、NAS が唯一の実体。HF で再取得できる公式パックに移れば、その単一障害点も解消できる。
- **(b) 常駐**: 無検閲 iQ パックと同じ ≈71GB wired と推定 (現行本命 ≈67GB の +4GB)。preflight の必要空きは約 77GB。11-08 の A/B で、無検閲 iQ パックのスワップは 4 回とも拒否されていない。推論中の wired のピークは、無検閲枠の実測 91.1GB と同程度と見込む。ディスクに 107GB の空きが要る。
- **(c) 期待 tok/s と品質**:
  - 速度は、同じ配分の無検閲 iQ パックの当機実測 (11-08、26.11.2、MTP on、llama-swap 経由) が short 71〜75、約 20k 後 66〜68、prefill 約 700。本命もこの水準と推定する (未実測)。
  - 現行本命の 26.10 以降の正式ベンチが無いので、**A/B の中で現行側も同じ手順で測る**。11-04 の簡易計測 87〜93 は手法が違うので比べない。
  - 品質は、nace-ai の第三者測定 (32,704 位置、mlx-vlm、BF16 比) で KL が Original 0.066 / Fresh 0.074。素の 4bit 系は 0.141 (nace-ai plain) 〜 0.249 (mlx-community)。
  - 現行本命 (4bit g64 + lm_head 8bit) の KL は誰も測っていない。素の 4bit 系と同じ水準と推定する。
- **(d) YAML 案**: 評価用の 3 本目のエントリ。`qwen38-flash-next` の直後に置く。

```yaml
  # ── 評価枠: 本命の imatrix 版 (ddalcu 公式、2026-10-01) ─────────────────
  # 無検閲枠 (AinsleyMarkov) と同配分 (experts/embed 4bit g64、他 8bit g64、imatrix)。BF16 比 KL 0.066 (nace-ai 測定)。
  qwen38-flash-next-iq:
    cmd: |
      ${settle}
      ${mlx_serve}
      --model /Users/joe/.mlx-serve/models/ddalcu/Qwen3.8-Flash-Next-MLX-Serve-iQ-MLX-4.7bpw
      --serve --host 127.0.0.1 --port ${PORT}
      --ctx-size 262144
      --timeout 0
      --prefix-cache-mem 12GB --prefix-cache-entries 64
    useModelName: Qwen3.8-Flash-Next-MLX-Serve-iQ-MLX-4.7bpw
    checkEndpoint: /health
    filters:
      setParams:
        enable_thinking?: true
    ttl: 7200
    aliases:
      - flash-next-iq
```

- **(e) 触る場所**:
  1. `mlx-serve pull ddalcu/Qwen3.8-Flash-Next-MLX-Serve-iQ-MLX-4.7bpw` を実行する。HF API の `?blobs=true` で 113 ファイルのサイズを照合する。
  2. 上のエントリを `dot_config/llama-swap/config.yaml` に追加し、`chezmoi apply ~/.config/llama-swap/config.yaml` → `launchctl kickstart -k gui/$UID/local.llama-swap`。
  3. `docs/bench/run_unc_iq.sh` を複製して、比較対象を `qwen38-flash-next` と `qwen38-flash-next-iq` にした A/B を回す (順序反転 2 周、tools 4 / code 5 / NIAH 2、日本語)。Hermes cron は停止中だが 09:00〜09:30 は避ける。
  4. 良ければ、既存エントリ `qwen38-flash-next` の `--model` と `useModelName` だけを差し替えて評価枠を消す。opencode / dsh / Hermes の変更は不要。
  5. 旧 4bit パックはローカルから消してもよいが、**NAS の実体は残す** (HF に無いため)。
