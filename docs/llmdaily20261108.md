対象機: MacBook Pro M4 Max 40C GPU / 128GB / macOS 26.x。構成は llama-swap → mlx-serve (Qwen3.8-Flash-Next の 2 パック)。
調査はクラウドサンドボックスで行い、本機では何も実測していない。数値は出典付きの他者実測か公式値で、当機向けの推定には「推定」「未実測」と書いた。

## (a) TL;DR

- **モデル: 据え置き**

### mlx-serve の既知の弱点の追跡

- **prefill 中に他のリクエストが止まる問題**: 26.10.x で既存ストリームの停止は改善済み (前回報告)。26.11.2 以降に追加の変更は無い。
- **プロセスを跨ぐスワップ直後の preflight**: main の `src/engines/mlx/runtime/preflight.zig` を読んだ。`waitForUnload` / `settledAvail` は「同一プロセスで直前に unload した `UnloadMark` がある場合」にしか待たない。仕様は変わっていないので、config.yaml の `settle` macro は引き続き必要。この件で Issue を探そうとしたが、github.com の Issue ページは 403 で読めなかった。
- **thinking の既定を on にするフラグ**: 追加されていない (`filters.setParams` による注入を継続)。26.11.2 の「effort word が思考を打ち切らない」変更は commit 0bfdff0 でタグに含まれている。

## (e) 推奨アクション

### 1. (任意) 無検閲 imatrix パックを 3 本目のエントリで A/B する

既定は据え置く。Hermes の既定エントリ名 `qwen38-flash-next-uncensored` は触らず、評価用のエントリを足す。

- (a) 形式: `AinsleyMarkov/Qwen3.8-Flash-Next-Uncensored-MLX-Serve-iQ-MLX-4.7bpw`。`library_name: mlx-serve`、arch `qwen4_exp` で、mlx-serve の converter (`431ac5d`) で作られている。現行パックとファイル構成が同じ (100 shard + vision + ngram_table.bin)。
- (b) 常駐: README は「約 75GB resident + KV」としている。ディスクのサイズとビット配分が ARC4NUM と同一なので、wired は現行 ≈70GB と同等、preflight の必要空きも約 77GB と推定する (未実測)。`settle` は同じように必要。**ディスクに 107GB の空きが要る。**
- (c) 期待 tok/s: 作者の A/B では比較パックとの速度比が 0.991 だったので、当機でも現行の無検閲枠 (11-04 簡易計測で 89 tok/s) と同等と推定する (未実測)。
- (d) YAML 案 (config.yaml の `qwen38-flash-next-uncensored` の直後に追加):

```yaml
  # ── 評価枠: 無検閲 imatrix 版 (AinsleyMarkov、2026-11-03) ─────────────────
  # base は現行と同じ orcarouter/Qwen3.8-Flash-Next-Uncensored。experts 4bit / 非 expert 8bit で ARC4NUM と同配分、
  # imatrix 重み付けで KL 0.18 → 0.11 (作者実測、M3 Ultra)。拒否率は未測定 → 拒否 3 問 / tools 4 問で確認してから昇格を判断。
  qwen38-flash-next-uncensored-iq:
    cmd: |
      ${settle}
      ${mlx_serve}
      --model /Users/joe/.mlx-serve/models/AinsleyMarkov/Qwen3.8-Flash-Next-Uncensored-MLX-Serve-iQ-MLX-4.7bpw
      --serve --host 127.0.0.1 --port ${PORT}
      --ctx-size 262144
      --timeout 0
      --prefix-cache-mem 12GB --prefix-cache-entries 64
    useModelName: Qwen3.8-Flash-Next-Uncensored-MLX-Serve-iQ-MLX-4.7bpw
    checkEndpoint: /health
    filters:
      setParams:
        enable_thinking?: true
    ttl: 7200
    aliases:
      - abliterated-iq
```

- (e) 触る場所:
  1. `mlx-serve pull AinsleyMarkov/Qwen3.8-Flash-Next-Uncensored-MLX-Serve-iQ-MLX-4.7bpw` を実行する。pull は欠落シャードを検出しないので、HF API の `?blobs=true` で 111 ファイルのサイズを照合する。
  2. `dot_config/llama-swap/config.yaml` に上のエントリを追加し、`chezmoi apply ~/.config/llama-swap/config.yaml` → `launchctl kickstart -k gui/$UID/local.llama-swap`。
  3. `docs/bench/bench_ab.py` で現行の無検閲枠と順序反転 2 周 + 拒否プローブ 3 問を回す。Hermes cron は停止中だが、09:00〜09:30 は避ける。
  4. 良ければ既存エントリ `qwen38-flash-next-uncensored` の `--model` と `useModelName` だけを差し替えて評価枠を消す。エントリ名を変えないので Hermes / opencode / dsh の変更は不要 (Hermes gateway の kickstart のみ)。
  5. ARC4NUM パックは NAS に退避してから削除する。
