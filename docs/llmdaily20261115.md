### 既知の弱点の追跡

- **prefill 中に他のリクエストが止まる問題**: 変更なし。
- **プロセスを跨ぐスワップ直後の preflight**: 変更なし。#1147 の新しい式でも、旧プロセスの wired が残っている間は拒否される。`settle` を維持する。
- **thinking の既定を切り替える手段**: CLI フラグは追加されていない。ただし、**26.11.2 にはすでに `~/.mlx-serve/generation-settings.json` (グローバル) と `model-settings.json` の `generation_defaults` (モデルごと) があり**、`{"enable_thinking": {"value": true}}` でクライアントが省略したときの既定を on にできる (docs/reference.md。リクエストごとに mtime を見て読み直す)。前回までの「追加なし」は、CLI フラグに限った話としては正しいが不正確だった。現行の llama-swap `setParams` 方式 (dotfiles 管理下、クライアントの `false` を尊重) で困っていないので、乗り換える必要は無い。設定ファイルは `~/.mlx-serve/` 配下にあり chezmoi の管理外なので、むしろ見えない設定が増えるのが欠点。

## (e) 推奨アクション

### 1. llama-swap v270 → v273 (低優先)

- 効く変更:
  - v272 #1319: 1MiB を超えるボディで `Expect: 100-continue` を送るクライアントに対し、上流のエラーが 200 に化けていたのを修正。
  - v272 #1327: `/props?autoload=false`。
  - v273: UI の改善 (capture ダイアログのタブ分割、Playground への画像貼り付け)。
- v273 の `fit` selector (#1340) は `routing.router.use: capacity` が前提で、複数のバリアントから空きに合うものを選ぶ機能。当機は排他で 1 モデルだけ常駐させる構成なので使わない。v271〜v273 の changelog に、config の互換性を壊す変更は無い。
- 手順: `brew upgrade mostlygeek/llama-swap/llama-swap` → `launchctl kickstart -k gui/$UID/local.llama-swap`。
- 更新後に部品表を書き換える。

```diff
-| llama-swap v270 | `/opt/homebrew/bin/llama-swap` | ...
+| llama-swap v273 | `/opt/homebrew/bin/llama-swap` | ...
```

### 2. mlx-serve

更新できるリリースが無いので、`run_onchange_after_install-mlx-serve.sh` への差分は無い。26.11.3 が出たら、次の手順で進める。
1. CHANGELOG に #1147 (preflight の新しい判定式、qwen4_exp の層ごとロード) が入っているかを確認する。
2. 入っていれば `MLX_SERVE_VERSION` / `MLX_SERVE_SHA256` を Formula の値に書き換えて更新する。`settle` macro は残す。
3. **更新後の初回ロードでアイドル時のウォームアップが走る** (b2eb804)。更新直後の簡易計測や A/B では、ウォームアップが終わってから測る。`run_unc_iq.sh` 型のスクリプトなら、計測しない 1 周を先頭に足すのが手軽 (llama-swap 経由では起動フラグを変えにくいため)。

### 3. (任意・継続) 本命パックの imatrix 版 A/B

前回 (e)-2 の提案は未実施。新しい根拠は無いので、YAML 案と手順は `docs/llmdaily20261112.md` の (e)-2 をそのまま使える。26.11.3 の更新と同じ時期にやるなら、上の 2-3 のウォームアップの注意も合わせる。
