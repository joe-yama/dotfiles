調査範囲は 2026-11-12〜11-23 (前回 `docs/llmdaily20261112.md` 以降)。リポジトリは 11-12 以降、LLM 関連の変更が無い (前回の推奨はどれもまだ反映されていない)。

## (a) TL;DR

- **モデル: 据え置き**
- **mlx-serve: 導入済み 26.11.2 / 最新リリース 26.11.3 (11-19) → 26.11.3 へ更新推奨。**
  - 前回「main に積まれている (未リリース)」と書いた以下の 3 件が、すべて 26.11.3 に入った。

    - #1163: prefill 待ち中に切断したときの SIGSEGV を修正。
    - #1151: 常駐量の計算に MTP キャッシュを含めるようにした。

  - 26.11.4 は pre-release のみ (Inkling 2 Mini 対応と `--os-reserve-gib` の修正)。main にはそれ以降、DeepSeek / Inkling 関連の 9 コミットがある (未リリース)。

### 1. mlx-serve 26.11.2 → 26.11.3 (推奨)

`run_onchange_after_install-mlx-serve.sh` の差分:

```diff
@@
-#       sha256 は Formula 掲載値 = Release asset digest)。
+#       sha256 は Formula 掲載値 = Release asset digest)。
+#       → 26.11.3 (<更新日>、preflight/admission が macOS の回収可能 RAM で判定 #1147・qwen4_exp の

@@
-MLX_SERVE_VERSION="26.11.2"
-MLX_SERVE_SHA256="550561d8bee59c40163da5e356d107fc290544c5f5d07d5add9943571b6930b5"

+MLX_SERVE_SHA256="a45db31a0a670dc551ed2f220719dc991a2ca13aaae9ec7d2a857625da7f32e4"
```

手順:
1. 上の差分を入れて `chezmoi apply --include=scripts` を実行する。run_onchange スクリプトは内容が変わったものだけ再実行され、ファイル (`~/.hermes/.env` を含む) には触れない。旧 26.11.2 は戻し用に残る。
2. `launchctl kickstart -k gui/$UID/local.llama-swap`
3. 確認:
   - 本命 → 無検閲 → 本命の順でスワップする。`~/.mlx-serve/logs/mlx-serve-<port>.log` の `[preflight]` 行で、判定値と拒否が無いことを見る。`settle` はそのまま残す。
   - (任意) Lightroom を開いたままロードし、11-03 の拒否が再現しないかを見る。
   - 短い速度確認: short / 約 20k 投入後の 2 点。26.11.2 (11-08 の無検閲 A/B) と同等なら OK。
4. 正本 `docs/local-llm-architecture.md` の部品表を `mlx-serve 26.11.3` に、preflight の段落を「26.11.3 からは回収可能 RAM 込みで判定」に更新する。

`--os-reserve-gib` を使う予定が無い限り、26.11.4 の正式版を待つ必要は無い。

### 2. llama-swap v270 → v275 (低優先)

- 効く変更:
  - #1319 (v272): `Expect: 100-continue` で 1MiB を超えるボディを送ったとき、上流の 400/500 が 200 に化ける不具合の修正。
  - #1354 (v274): ボディ付きの POST にだけ JSON フィルタをかける。
  - #1358 (v274): 自分のモデル ID と同じ alias を起動時に拒否する。
- 当機の alias (`flash-next` / `default` / `abliterated`) はモデル ID と一致しないので、#1358 で起動が失敗することは無い。
- v273 の `fit` selector は、capacity router 前提で同じモデルの小さい版を選ぶ機能。当機は 2 本の排他スワップなので不要。
- 手順: `brew upgrade mostlygeek/llama-swap/llama-swap` → `launchctl kickstart -k gui/$UID/local.llama-swap` → 部品表を `v275` に書き換える。

```diff
-| llama-swap v270 | `/opt/homebrew/bin/llama-swap` | ...

```

### 3. (任意、(e)-1 の後) `X-MLX-Priority` が Flash-Next で効くかを確かめる

config は変えない。llama-swap 経由で次の 2 本を同時に投げ、B の TTFT を比べる。
- A: 約 20k トークンの長文 (`docs/bench/` の素材)
- B: 短い tool 呼び出し。ヘッダ無し / `-H 'X-MLX-Priority: high'` の 2 通り

B の TTFT が「A の prefill 完了待ち (約 28 秒、prefill 700 tok/s から推定)」から数秒に縮めば、次の 2 つを検討する価値がある。
- Hermes / dsh の短い補助呼び出しにヘッダを付ける
- 長い prefill 中も decode が進むかを見る

縮まなければ、qwen4_exp はまだ対象外と判断して追跡を続ける。
