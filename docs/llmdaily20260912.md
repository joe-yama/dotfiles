## (e) 推奨アクション

### 1. mlx-serve 26.9.1 → 26.9.2 (推奨)

`run_onchange_after_install-mlx-serve.sh` の差分 (sha256 は本サンドボックスで release tarball 71,033,617 bytes を取得して算出し、Formula の値と一致):

```diff
-MLX_SERVE_VERSION="26.9.1"
-MLX_SERVE_SHA256="b9bb5178ac2dcfbfa232ffa1e6ce77e87a6408a540cbdaabb66d101d667590b0"
+MLX_SERVE_VERSION="26.9.2"
+MLX_SERVE_SHA256="f2dd5f80d4e50e4ebd57b28e70ce79ed95a657337360784975b610cec50400af"
```

手順: `chezmoi apply ~/.local/opt/mlx-serve` 相当 (run_onchange が再実行される) → `launchctl kickstart -k gui/$UID/local.llama-swap`。旧 26.9.1 は `~/.local/opt/mlx-serve/mlx-serve-26.9.1` に残るので、問題があれば version/sha を戻して apply。Hermes cron の 09:00〜09:30 を避ける。

更新後に確認したいこと (実機、`docs/bench/` のハーネスで):
- MTP off の短文 / 24k 後 decode が 70 / 58 tok/s から落ちていないこと (退行チェック)。
- `--mtp` を付けた A/B。26.9.2 は文脈長で自動 off になるので、09-05 に見た 24k 後 −14% が消えていれば、本命にも `--mtp` を付ける価値がある (ddalcu 実測 +50% 短文は MTP 前提の数字。当機の期待値は 74.5 → 80 台、未実測)。
- opencode の reasoning effort `xhigh` で #395 の早期停止が出るか。

### 2. llama-swap v252 → v255 (推奨、低リスク)

`brew upgrade mostlygeek/llama-swap/llama-swap` (Brewfile はバージョン固定なし) → kickstart。LaunchAgent の `--config` / `--listen` は変更なし。
併せて config.yaml の thinking 注入を soft default にする案 (任意):

```yaml
  qwen38-flash-next:
    cmd: |
      ${mlx_serve}
      --model /Users/joe/.mlx-serve/models/ddalcu/Qwen3.8-Flash-Next-MLX-Serve-4bit
      --serve --host 127.0.0.1 --port ${PORT}
      --ctx-size 262144
      --timeout 0
      --prefix-cache-mem 12GB --prefix-cache-entries 64
    useModelName: Qwen3.8-Flash-Next-MLX-Serve-4bit
    checkEndpoint: /health
    filters:
      setParams:
        # v255 の set-if-undefined: クライアントが enable_thinking を送らなければ on、
        # 明示的に false を送れば尊重する (llama.cpp 時代と同じ挙動)。
        enable_thinking?: true
    ttl: 7200
    aliases:
      - flash-next
      - default
```

`qwen38-flash-next-uncensored` も同様に `enable_thinking?: true`。Hermes は `enable_thinking` を送らないので常時 on のまま (要件維持)。**v252 のままこの書き方にすると `enable_thinking?` という無効キーとして上流に渡る**ので、brew upgrade 後に変更すること。現状の「クライアントの off も上書きしたい」方針を維持するなら config は触らず brew upgrade だけでよい。

### 3. モデル: 変更なし

`qwen38-flash-next` / `qwen38-flash-next-uncensored` とも据え置き。yomie4343 パックは ARC4NUM と同一重みなので無視。

### 4. 任意の実験 (推奨ではない)
- `--prefix-cache-disk`: dsh 3 セッション × 150k のような使い方で 12GB 枠が溢れる場合の SSD 階層。まず現行 12GB で溢れているかを llama-swap ログで確認してから。
- `--max-mtp-ctx 32768` を `--mtp` と併用: 自動判定に任せず 24k 後は必ず serial にしたい場合。
