# 無検閲枠 A/B: ARC4NUM mixed 4/8bit vs AinsleyMarkov iQ-MLX-4.7bpw (2026-11-08)

`docs/llmdaily20261108.md` の推奨アクション (e)-1 の実施記録。**結果: 同等なので `qwen38-flash-next-uncensored` の実体を AinsleyMarkov 版に差し替えた。**

- G = 旧 `ARC4NUM/Qwen3.8-Flash-Next-Uncensored-MLX-Serve-4bit` (mixed 4/8bit、min-max 量子化)
- H = `AinsleyMarkov/Qwen3.8-Flash-Next-Uncensored-MLX-Serve-iQ-MLX-4.7bpw` (同系譜・同配分 + imatrix、HF rev `cc9f395`)
- 両アームとも llama-swap 経由 (本番の cmd・`settle`・MTP 既定 on)、mlx-serve 26.11.2、`run_unc_iq.sh` で G H | H G の順序反転 2 周、
  周ごとにプロセスを立て直す。各周 short 3 run 中央値、run 間 20 秒・アーム間 90 秒クールダウン、拒否プローブ付き。
- 長文素材は `man zshall` (col -bx、86k 文字 = 約 19.8k トークン)。2026-09-05 の素材 (23.7k トークン) とは別物なので、
  24k 後 decode / prefill の絶対値は 09-05 の表と直接比べない。
- 作者 README の比較パック yomie4343 mixed-4-8bit は ARC4NUM と全ファイル SHA-256 一致 (docs/llmdaily20260916.md) なので、
  作者の KL / top-1 比較 (KL 0.18 → 0.11、code top-1 83.5 → 90.9%、math 96.2 → 88.8%) はそのまま G 対 H の比較になる。

## 判断

速度・tools・code・NIAH・拒否は差が無く、局所プローブでは品質差を検出できない。レポートが昇格条件に挙げた
拒否 3 問 / tools 4 問を満たし、作者の BF16 比 KL が改善している (math の top-1 低下は低確信度位置に偏る) ので差し替えた。
戻すときは config.yaml の `--model` と `useModelName` を ARC4NUM に戻す (NAS と HF に残っている)。
